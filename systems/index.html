Platform layers

The components our systems are assembled from.

These are not products and are not sold separately. They are listed because a buyer evaluating a small firm is entitled to know whether the depth is real or whether each engagement starts from nothing.

  • Async tool-calling engineConcurrent tool execution with per-call timeouts, retries and structured failure — so a stalled dependency degrades one branch rather than the run.
  • Deterministic retrieval and orchestrationRetrieval whose result set is reproducible from the run record, and orchestration whose control flow is code rather than model discretion.
  • Multi-agent workgroup environmentSpecialised agents working under one orchestrator, with the boundary at which each may act declared before the run.
  • Model routingTask-appropriate model selection, so the expensive model is used where judgement is needed and nowhere else.
  • CLI orchestrationEvery pipeline runnable head-less and reproducibly, which is what makes trace replay possible at all.
Internal tooling

The agent estate.

Specialised, versioned agent directives in production across research synthesis, course architecture, patent prosecution, financial analysis, technical illustration and editorial work. We do not publish a count, because anyone can claim one. Three specifics are more useful:

  • 01An epistemic control agent whose only function is to stop vague, unfalsifiable or overreaching claims reaching a final output.
  • 02Adversarial reviewer agents that argue against a conclusion before it ships, rather than checking it after.
  • 03A closed output vocabulary wherever a system emits a verdict — including a refusal state, so "cannot answer" is a first-class result rather than a silent gap.
